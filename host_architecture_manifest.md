# Манифест архитектуры адаптивного хоста

## 1. Общая идея

Система строится по принципам, аналогичным неокортексу: канонические колоночные микроконтуры, непрерывное время, предиктивное кодирование и минимизация свободной энергии (Active Inference). Цель — не монолитная LLM, а модульный, консистентный во времени хост-собеседник/со-игрок, способный к ситуационному обучению, обладающий чувством времени, эмоциональной динамикой, устойчивым характером и способностью к автономной эволюции.

Ключевой принцип — **экологическая рациональность**: система не считает всё возможное байесовски строго, а считает только то, что необходимо, экономя вычислительные ресурсы (event-triggered inference, разреженная факторизация, эвристические быстрые пути).

## 3. Ключевые подсистемы

### А. Кортикальная ткань (Canonical Microcircuits)
- Узел: слои L4 (вход) → L5/6 (генератор состояния x(t)) → L2/3 (ошибка предсказания e(t)).
- Специализация колонок по узким проекциям реальности: тон, ритм, задачи, ToM, сенсоры MCP.
- Голосование через латеральное торможение (k-WTA) — консенсус без центрального контроллера.
- Параллелизм: батч колонок в единый тензор `[N_columns, In_Dim, State_Dim]`, обсчет за один такт SIMD на CPU.
- Масштабирование горизонтальное и линейное (O(N)) — новые колонки не увеличивают сложность существующих (в отличие от квадратичного роста трансформеров).

### Б. Непрерывное время и интероцепция
- Циркадные гармоники (sin/cos фазы суток), интервальный счетчик пауз, субъективный темп (ускоряется при росте F(t)).
- Валентность = -dF/dt; аллостатический стресс = интеграл F(t) по времени; точность (γ) = обратная дисперсия входного сигнала.
- Эти четыре сигнала формируют аффективный модификатор, передаваемый в речевой актюатор.

### В. Целеполагание (Hierarchical Active Inference)
- Root Priors — постоянные ценности (когерентность, целостность, верификация).
- Task Goal — временные динамические аттракторы задач с TTL и приоритетом; при простое энергия задачи растёт, хост сам напоминает о ней.
- Epistemic Drive — в отсутствие задач хост ищет области максимальной неопределённости и исследует их сам (любопытство).

### Г. Социальный контур
- Упрощённая Theory of Mind: скаляр/вектор `partner_trust`, `partner_state` — оценка согласия, двусмысленности, конфликта.
- Joint Agency — совместные целевые аттракторы для игровых/рабочих сценариев (хост подстраховывает, а не просто исполняет).
- Vigilance Gate — новые утверждения оператора маркируются как гипотезы, пока не подтвердятся практикой; защита от эпистемического дрейфа.

### Д. Память (Complementary Learning Systems)
- Быстрый буфер: SQLite + sqlite-vec, эмбеддинг-прецеденты правок и ситуаций (доли миллисекунды на запрос).
- Консолидация во сне: active pruning неважных эпизодов + Structure Learning (обобщение повторяющихся паттернов в схемы).
- Почему SQLite, а не Postgres/pgvector: embedded-архитектура даёт 0.1–0.5 мс задержки и нулевой фоновый процесс — оптимально для одного локального пользователя; переход на Postgres оправдан только при многопользовательском/распределённом сценарии.

### Е. Экологическая рациональность и гибридный расчёт
- Event-Triggered Active Inference: полный пересчёт запускается только при F(t) выше порога; иначе система дрейфует по инерции.
- Recognition Heuristic: типовые ситуации (приветствие, подтверждение) закрываются мгновенным шаблоном без обращения к LLM.
- Разреженная факторизация вместо единой POMDP-матрицы: 3 независимых маленьких фактора (режим/партнёр/задача) вместо комбинаторного взрыва в `pymdp`.
- `pymdp` используется точечно — для 4–8 дискретных макро-состояний; вся непрерывная динамика — на NumPy/SciPy.

### Ж. MCP как органы чувств и действия
- MCP Resources — фоновая пассивная сенсорика (погода, локация, статус устройства), подмешивается в u(t) на медленном такте.
- MCP Tools — активные эпистемические действия: вызываются, когда неопределённость выгоднее снизить внешним запросом, чем предполагать.
- MCP Actions — исполнительные инструменты, физическое/цифровое воздействие на среду.
- Список доступных MCP формирует "карту аффордансов" хоста — пространство того, что он в принципе умеет.

## 4. Трек речи: от мегапромпта к выращенной речи

```
 Б1: Мегапромпт (Intent-Frame) → Б2: Activation Steering → Б3: Steering + CMLA → Б4: Emergent/Реактивная речь
```

- **Б1. Мегапромпт-прокладка.** Ядро формирует структурированный Intent-Frame (цель реплики, аффект, прецеденты, стиль) и передаёт его в облачный LLM API. Риск: модель может «сжимать, переинтерпретировать, пропускать» часть инструкций при их накоплении.
- **Б2. Activation Steering на локальной SLM.** Переход на локальную модель (Gemma-3-4B / Qwen3-1.7B, MLX/HF transformers на M2 8GB) даёт прямой доступ к forward hooks: вектор состояния ядра x(t) инжектируется в residual stream модели, минуя текст. `EvolvingSteeringMemory` копит и уточняет вектор "характера" из контрастных пар правок оператора — так речевой стиль хоста буквально формируется опытом, а не переписыванием промпта. Ограничение: управляет только поведенческими осями (тон, уверенность, лаконичность), не фактами.
- **Б3. Гибрид Steering + CMLA.** Параллельно собирается корпус "речи, направленной на хоста" — узкий, ситуативный аналог Child-Directed Speech из реального взаимодействия. Внешняя/локальная LLM выступает наставником: генерирует эталонные ответы, на которых компактная продукционная модель хоста учится картировать смысл → речь, по методологии computational modelling of language acquisition. Это явно замкнутый цикл "учитель-ученик", где сама языковая модель — источник обучающих сигналов для младшей системы.
- **Б4. Реактивная колоночная речь (горизонт).** Экспериментальное направление Emergent Communication: колонки хоста вырабатывают собственный композиционный протокол для решения задач без предзаданной грамматики (Neural Iterated Learning, фонетико-лексическое обучение с нуля). Честная оценка: пока академический фронтир без production-инструментов; результат — не обязательно естественный язык, а эффективный внутренний протокол, требующий финального переводного слоя во внешнюю речь.

## 5. Дорожная карта (4 фазы) с синхронизацией трека речи

| Фаза | Основное ядро | Трек речи | Критерий готовности |
| :--- | :--- | :--- | :--- |
| **1. Реактивный MVP** (1–2 нед.) | Непрерывное ядро x(t) на NumPy, расчёт F(t), эпизодическая память в SQLite, экологичный вызов Embeddings/LLM API | Б1: Мегапромпт (Intent-Frame) | Хост запоминает правки с одного раза, меняет тон при расхождении |
| **2. Сенсорный агент** (2–4 нед.) | Циркадное время, интервальные паузы, интеграция MCP (resources+tools), динамические аттракторы задач | Б2 (старт): переход на локальную SLM, подготовка hooks | Хост напоминает о незавершённой задаче, учитывает время суток |
| **3. Со-игрок (ToM)** (1–2 мес.) | Ансамбль колонок (CMC Fabric) с латеральным голосованием, модель партнёра, Vigilance Gate, Joint Agency | Б2 (зрелость) → Б3 (старт): `EvolvingSteeringMemory` работает, сбор корпуса CDS-аналога | Хост подстраховывает игрока, распознаёт манипуляции и блеф |
| **4. Зрелый автономный субъект** (2–3 мес.) | Ночной сон (active pruning + Structure Learning), эпистемический драйв, снятие ролевых приоритетов (γ_persona → 0) | Б3 (зрелость) → Б4 (эксперимент): продукционная модель учится у LLM-наставника, первые опыты Emergent Communication | Хост неделями работает автономно, оптимизирует память, развивает собственный стиль |

## 6. Критическая оценка (риски и ограничения)

1. **Free Energy Principle — не готовый рецепт, а спорная гипотеза.** Критики указывают на низкую фальсифицируемость FEP; ретроспективные проекты показывают, что active inference часто не даёт измеримого преимущества над обычным RL/эвристиками. Рекомендация: на каждом этапе держать простую эмпирическую альтернативу и сравнивать реальный выигрыш.
2. **Масштабирование генеративной модели остаётся открытой проблемой** — гибрид дискретного/непрерывного ядра обходит, но не решает эту сложность; потребуется эмпирическая калибровка порогов и коэффициентов.
3. **Мегапромпты хрупки** — модели «сжимают, переинтерпретируют, пропускают» инструкции при их накоплении; это прямая причина двигаться к Activation Steering как можно раньше.
4. **Риск тихого дрейфа состояния (Silent State Drift)** — накопительная память и эволюционирующие приоры могут незаметно увести поведение хоста от нормы. Необходим явный лог телеметрии (`[F | Valence | State]`) и метакогнитивный слой самодиагностики ("я запутался, нужен ручной сброс"), который в базовой версии манифеста был неявным и должен стать architected first-class компонентом.
5. **Steering не заменяет знания** — управляет тоном и стилем, но не фактической точностью; для фактов остаются MCP/RAG.

## 7. Технологический стек

| Компонент | Технология | Роль |
| :--- | :--- | :--- |
| Сенсорика и действия | MCP-серверы (Resources + Tools) | Органы чувств и манипуляторы |
| Входной адаптер | Embeddings API (или локальный MiniLM ONNX) | Текст → непрерывный вектор |
| Колоночное ядро | NumPy / PyTorch CPU (SIMD-батчинг) | Динамика x(t), F(t), эмоции, ToM |
| Дискретная логика верхнего уровня | `inferactively-pymdp` (точечно, 4–8 состояний) | Макро-режимы, целеполагание |
| Эпизодическая память | SQLite + sqlite-vec | Прецеденты, консолидация, EvolvingSteeringMemory |
| Речевой актюатор (Фаза 1) | Внешний LLM API + Intent-Frame | Быстрый старт |
| Речевой актюатор (Фаза 2+) | Локальная SLM (Gemma-3-4B / Qwen3-1.7B, MLX/HF transformers) + Activation Steering | Управление тоном без текстовых инструкций |
| Речевой актюатор (Фаза 3–4) | Продукционная модель, обучаемая у LLM-наставника (CMLA) | Выращенная изнутри речь |

## 8. Режимы жизненного цикла (гибкость роли)

| Режим | Ролевые приоритеты (γ_persona) | Источник целей | Свобода |
| :--- | :--- | :--- | :--- |
| Игровой аватар | Зафиксированы (лор игры) | Любопытство в рамках характера | Устойчивый отыгрыш |
| Адаптивный со-игрок | Частично пластичны | Совместные задачи + ToM | Подстройка под конкретного человека |
| Свободный хост | Полностью пластичны (→0) | Эпистемический драйв, личный опыт | Автономная эволюция личности |

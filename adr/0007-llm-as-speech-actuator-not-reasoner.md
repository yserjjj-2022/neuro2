# ADR-0007: LLM — речевой актюатор (зона Брока), не центр рассуждения

## Date
2026-09-27

## Status
Accepted

## Context

При реализации S3 (голос) обнаружено: reasoning-модели (напр.
`deepseek/deepseek-v4.1-flash` на RouterAI) при вызове чата тратят токены на
внутреннее «размышление» и возвращают **пустой `content`** при небольшом
`max_tokens` (`finish_reason: length`, токены ушли в `reasoning_tokens`).
Замер: 50 токенов reasoning, `content=''`. Только `reasoning_effort='low'`
или полное отключение (`reasoning: {enabled: false}`) дают нормальный ответ.

Возник вопрос: нужен ли ризонинг в речевом слое вообще.

Архитектурный контекст:
- Манифест §3.5/§5: LLM — «экологичный речевой актюатор», озвучивающий
  сформированное ядром намерение.
- ADR-0003 уже фиксирует риск: «мегапромпты хрупки — модели сжимают,
  переинтерпретируют, пропускают инструкции при накоплении».
- Рассуждение/планирование в архитектуре принадлежит **ядру**: колоночная
  ткань, F(t), аттракторы; в будущем — policy (S4) и дискретный слой (S6).

## Decision

**LLM в этом проекте — речевой актюатор (аналог зоны Брока), а не центр
рассуждения. Reasoning у LLM по умолчанию отключён.**

Обоснование по аналогии: зона Брока **артикулирует** уже сформированное
намерение, не планирует и не решает. Префронтальное рассуждение и рабочая
память — это ядро, а не речевой слой.

Конкретно:
1. `ApiLlmClient` вызывает chat с `reasoning: {enabled: false}` по умолчанию.
2. `SpeechConfig.reasoning` (bool, дефолт False) + CLI `--reasoning` —
   ручка на будущее (когда ядро научится формировать сложные намерения и
   захочет «развернуть» их, напр. в register `story`).
3. Токены reasoning не тратятся; ответы детерминированнее по форме
   (меньше «переосмысления» Intent-Frame).

## Consequences

### Положительные
- Единственный центр принятия решений — ядро (не дублируется в LLM).
- Intent-Frame не «переинтерпретируется» моделью — меньше риск ADR-0003.
- Дешевле и быстрее (нет reasoning-токенов; не нужен большой `max_tokens`).
- Речь предсказуемее по форме (важно для register/адекватности).

### Отрицательные
- Пока ядро не умеет рассуждать (policy — S4, дискретный слой — S6), хост
  отвечает рефлекторно на уровне формулировки. Для S3 (голос) это приемлемо.
- Reasoning-возможности модели не используются; при необходимости включаются
  флагом.

### Tradeoffs
- **Автономность LLM vs чистота архитектуры:** ризонинг в LLM дал бы
  «умнее» ответы ценой дублирования центра решений и роста риска дрейфа
  Intent-Frame. Выбран архитектурный принцип: рассуждение — в ядре.

## Confidence
High для S3. Принцип следует из манифеста (LLM — актюатор) и ADR-0003
(хрупкость промптов). Пересмотреть, когда появится policy (S4): если ядро
будет формировать развёрнутые намерения, `reasoning=True` может стать
уместным для register `story`.

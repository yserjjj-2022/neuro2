# ADR-0015: Прагматическая оценка опций относительно цели

## Status
Accepted

## Date
2026-02-19

## Context

В S8 этапах 1–5 `score_option` всегда возвращал `pragmatic = 0.0` (`compute.py:147`):
семантика эффекта была объявлена, но не влияла на выбор. При введении цели
(ADR-0014) возникает вопрос: как прагматическая ценность опции зависит от
выбранной цели и какова единая семантика `effect.value`.

## Decision

### 1. Прагматическая ценность — доля закрытия текущего разрыва

Для выбранной цели `goal` и снимка фактов `facts`:

```
d_до = goal.value − current
d_после = goal.value − effect.value
P = clip((d_до − d_после) / d_до, 0, 1),   d_до > ε
P = 0,                                       цель уже достигнута
```

где `current = evaluate_fact(goal.fact, facts)`. Чужой эффект
(`effect.fact.name != goal.fact.name`) или отсутствие эффекта → `0`.

Приоритет цели учитывается **отдельно** (в `select_goal`, ADR-0014 §4), не
внутри `P`.

### 2. `effect.value` — прогнозируемое итоговое значение факта

`effect.value` — **прогнозируемое итоговое значение факта** ∈ [0, 1] после
применения опции, а не приращение. Формула `d_после = goal.value − effect.value`
применяется **напрямую**, без сложения с `current`. Это значение используется
одинаково в `effect_gain` (скорер) и в `backward_chain` (при оценке подцелей).

Если реальный эффектор отдаёт приращение — Shell приводит к итоговому значению
**до** передачи в Core.

### 3. Граница оценки

`P` — оценка прогресса для MVP, **не гарантия оптимальности планирования**.
Промежуточные шаги без прямого прогресса должен обеспечивать `backward_chain`
(подцели через `guard`). Оценки близости к цели допускают **локальные ловушки**;
MVP их не устраняет.

### 4. Аддитивность

`score_option` возвращает `pragmatic = effect_gain(...)`, если `context.goal`
задан, иначе `0.0` (обратная совместимость с этапами 1–5). Новые параметры
`backward_chain` (`context`, `preferences`) — keyword-only с `None`: при их
наличии опция, достигающая факта цели, выбирается как лучшая по `score_option`,
а не первая по окну.

## Implications

- `pragmatic` реально влияет на выбор, а не только на трассу.
- `Guard` по-прежнему гейтит через генератор (`Sequence(subtree, action)`),
  не через скорер: pragmatic — ценность, guard — предпосылка (ADR-0012 §3).
- `effect_gain` — чистая функция, тотальная: неизвестный факт деградирует к
  `fact.default`, пустой снимок → `0`.

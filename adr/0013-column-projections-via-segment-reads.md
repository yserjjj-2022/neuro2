# ADR-0013: Проекции колонок через именованные reads сегментов

## Date
2026-10-11

## Status
Accepted

## Context

Колоночный ансамбль (`src/core/cmc/`) сегодня вырожден: `CMCEnsemble.step(u)`
передаёт **один и тот же полный вектор** `u(t)` каждой колонке
(`ensemble.py`, `column_step`), состояния инициализируются нулями. При
одинаковом `alpha` (дефолт 0.1) состояния и ошибки всех колонок численно
совпадают — «три колонки» суть три копии одного фильтра. `specialization` —
тег, не влияющий на вычисления (`ColumnConfig`, SPEC cmc).

Следствия вырождения:
- выбор задачи (k-WTA / аттрактор по `activities = Σe²`) не различает
  «предметы» обработки — только разрешает ничью по индексу;
- `active_columns`/`active_tags` не отражают, какой срез среды возмущён;
- дальнейшие механизмы (важность каналов, attention-гейт) работают поверх
  неразличимых интерпретаторов.

Доставка сигналов (шина `u(t)`, карта сегментов, реестр интеграций) уже
устроена; не хватает **различной обработки** доставленного. Это ограничение
уровня обработки, а не доставки.

Ограничения:
- CONSTITUTION §2.1: единый тензор `[N, In, State]` — у всех колонок общие
  `input_dim`/`state_dim`; подвектор на колонку ломает инвариант.
- ADR-0004: Functional Core / Imperative Shell (`column_step` — Core,
  `CMCEnsemble` — Shell).
- ADR-0011: реестр интеграций — источник состава шины и карты сегментов.
- ADR-0005 §2: attention-гейт (γ) — пред-колоночный барьер; в этом шаге не
  трогается.

## Decision

### 1. reads — именованные сегменты, не индексы

`ColumnConfig.reads: tuple[str, ...] | None` — имена сегментов шины (валюта
реестра/карты сегментов), не индексы/срезы. `None` → весь вход (legacy).
Разрешение имён → бинарная маска происходит **при сборке** ансамбля, до
первого тика; состав сегментов фиксирован в прогоне (смена состава → пересборка).

### 2. Маска означает «не наблюдается», а не «наблюдается ноль»

Маска `m_j` (бинарная, `bus_dim`) входит **внутрь** обновления состояния и
расчёта ошибки:

```
x_{j,t} = x_{j,t-1} + α_j · m_j ⊙ (u_t − x_{j,t-1})
e_{j,t} = m_j ⊙ (u_t − x_{j,t})
```

Нечитаемые координаты: не обновляют состояние, не создают ошибку, не
участвуют в активности, тегах и энергии. Ноль на отключённой координате не
становится фиктивным наблюдением (это отличие от подачи `m⊙u` в прежний
фильтр).

`reads=None` → `m_j ≡ 1` → формулы тождественны прежним.

### 3. Единый ансамбль, разные предметы — не ансамбль на канал

Принято: **1 ансамбль : 1 общий вход : N колонок с разными reads**. Отвергнута
альтернатива «ансамбль на сенсорный канал»: маршрутизация по отдельным каналам
уже есть (гомеостат/рефлекс по tag), а ценность ансамбля — в гипотезах о
**связях** между каналами (мультиканальные reads). Также отвергнут подвектор на
колонку (нарушает §2.1).

### 4. Три правила агрегации — раздельны, legacy сохранён

| Величина | Правило | Обоснование |
|---|---|---|
| k-WTA / аттрактор | `Σ e²` по координатам (legacy) | В первом пресете reads равной ширины → `Σ = n·mean` → эквивалентность ранжирования; менять метрику — отдельный шаг |
| `active_columns` | `Σ e² > active_threshold` (абсолютный порог, legacy) | Порог кормит fingerprint/behavioral_chain; переход на среднее сдвинул бы отпечатки |
| Глобальный FFF | `Σ` по всем колонкам (legacy) | FFF — якорь экспериментальной истории; формула не должна зависеть от конфигурации reads |

Равная ширина reads гарантирует эквивалентность **ранжирования** sum/mean, но
не всей динамики аттрактора (dwell/basin/plasticity). Точный legacy-контракт
относится к `reads=None`, где `m ≡ 1` и числа совпадают тождественно.
Нормировка активностей (mean) и её влияние на `argmax` при разной ширине —
отдельный шаг со своим ADR и перепечаткой отпечатков.

### 5. Перекрытие проекций: FFF = суммарная ошибка модулей

Семантика: глобальный FFF — общая ошибка всех модулей; повторное чтение канала
несколькими колонками **увеличивает** вклад канала. Дублирование колонки
добавляет её вклад в FFF (а не обязательно удваивает весь FFF). Агрегация с
фиксированным весом канала (невосприимчивая к числу читающих) — отдельный ADR
при необходимости.

Абсолютные значения FFF между разными конфигурациями reads автоматически не
сопоставляются (FFF зависит от числа колонок и перекрытия).

### 6. Победитель k-WTA = «наиболее требующая внимания специализация»

Разные reads дают разные предметы обработки, но `argmax` по ошибке означает
«наибольшее рассогласование с наблюдением», а не «лучшее объяснение». Для MVP
это полезный и честный смысл; конкуренция объясняющих гипотез требует
отдельного обоснования оценок. Ничьи разрешаются детерминированно
(минимальный индекс, stable `argsort`) — это записанное правило, не следствие
разных reads.

### 7. Карта сегментов полна, включая memory

Разрешение reads идёт по **полной** карте входных сегментов ансамбля, включая
сегмент памяти (`memory`, offset `bus_dim`, dim `prior_dim`), который пока
добавляется вне реестра. Иначе часть входа недоступна явной конфигурации
проекций. Перенос памяти в реестр — отложен; карта полна уже в этом шаге.

### 8. Сборка — fail-fast

Неизвестное имя сегмента, пустой `reads`, повтор имени, `reads` при отсутствии
карты сегментов → `ValueError` **до первого тика**. Наблюдаемость: ансамбль
экспонирует `resolved_reads` (фактические сегменты каждой колонки); host
логирует их при сборке.

### 9. Вне скоупа этого шага

Нормализация единиц/масштаба каналов, разные `alpha` (тривиатор временных
шкал), a-priori ошибка (`e_pred = u_t − x_{t-1}` отдельно от остатка), вывод
весов attention-гейта, mean-активности. Каждое — отдельным изменением, чтобы
причинный эффект проекций был атрибутируем.

## Consequences

### Положительные
- Колонки начинают обрабатывать разные объявленные части среды (не копии).
- Избирательное возмущение канала затрагивает только читающие колонки.
- `active_tags`/`channel_contrib` отражают срез, а не общий вход.
- Основа для дальнейшей специализации (нормировка, alpha-шкалы) — без перелома
  инварианта `[N, In, State]`.

### Отрицательные
- Ещё один параметр конфигурации (`reads`) и слой разрешения масок.
- FFF зависит от перекрытия reads → межконфигурационное сравнение F
  неавтоматично.
- Ожидаемое поведение скромное: «разные объявленные области обработки», а не
  «выбор интерпретации мира».

### Tradeoffs
- **Маска vs подвектор:** маска сохраняет §2.1, но требует семантики «не
  наблюдается» (нули не фиктивны); подвектор чище семантически, но ломает
  инвариант.
- **reads по именам vs индексам:** имена устойчивы к перестановке ростера и
  совпадают с валютой реестра; индексы хрупки.
- **sum vs mean активностей:** sum — legacy-совместимость; mean — сравнимость
  разной ширины; выбран sum (mean — отдельный шаг).

## Confidence
Medium-High. Семантика маски и legacy-контракт `reads=None` следуют из формул;
три правила агрегации — из текущего кода (`wiring.py`, `ensemble.py`) и
требования не сдвигать отпечатки. Эквивалентность sum/mean при равной ширине
ограничена ранжированием (не всей динамикой аттрактора).

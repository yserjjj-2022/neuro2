# ADR-0008: Атрибуция, узнавание и имена агентов

## Date
2026-09-27

## Status
Accepted

## Context

При обсуждении S3–S5 всплыли четыре неразведённых вопроса о том, как хост
относится к собственным состояниям и к собеседнику:

1. **Атрибуция состояний.** У хоста есть сырые сигналы (F, valence, stress,
   γ, ресурсы), но нет ответа «что это за переживание и отчего».
2. **Дилемма ярлыков.** Дать описания заранее («это ты волнуешься», «батарея
   садится») или выращивать в диалоге?
3. **Субъект диалога.** CLI не подписывает собеседника. Как хост узнаёт, с кем
   говорит, и запоминает имя?
4. **Мультиагентность.** Для сценариев «хост — Мастер игры» и будущей
   мультиагентной среды нужны персональное восприятие и адаптация под разных
   агентов.

Ограничения:
- INTENT level A: не программировать поведение, выращивать правила.
- ADR-0003/0007: LLM — речевой актюатор (зона Брока), не центр рассуждения.
- ADR-0006: непрерывность; рациональный контур event-triggered.

## Decision

### 1. Ярлык — коммуникативный слой, не поведенческий

Поведение управляется **сырым сигналом** (ядро, S4 policy). Словесные ярлыки
состояний («напряжение», «тревога») нужны только для **коммуникации** и на
поведение не влияют. Это снимает дилемму «предзадано vs обучить»:

- **Язык ярлыков приходит извне** (диалог) — словарь социален.
- **Привязка «паттерн ↔ слово» выращивается изнутри** (опыт, вес в памяти).

Не таблица «stress>5 → тревога» (это было бы программированием), а
ассоциативная память: ключ — паттерн интериоцепции, значение — слово/фраза.
Частое закрепляется весом; редкое даёт честную неопределённость описания.
**Отдельного хранилища лексикона нет** — это домен общей памяти.

### 2. Источник — система отсчёта, не категория

Различие «я / не-я» не является тегом, который нужно присваивать: оно уже
структурно присутствует в данных.

- **Своё** (интеро): `valence/stress/free_energy` в `Episode` — единично по
  построению (одно тело, один поток).
- **Чужое** (партнёр/мир): `content` (текст) — открытое множество.

Поэтому **не вводится тег `source`**. Вводится способность **заметить** это
разделение (метакогниция, S4), а не новая сущность в памяти.

### 3. Персона — вывод из регулярности, а не декрет

Агент моделируется как **предиктивная модель источника** (узнавание = снижение
неопределённости предсказания, FEP):

- **Сигнатура партнёра:** стиль/лексика (эмбеддинг текста), тайминг,
  предпочтения (реакции valence/stress), история взаимодействий.
- **Узнавание:** матчинг новой реплики к существующим сигнатурам по сходству.
- **Число агентов обучается**, не фиксируется (эмерджентное множество;
  путь к мультиагентности).

Идентичность — не профиль и не тег, а **вывод** из устойчивой регулярности.
Идентичность хранится как **домен общей памяти** (сигнатура → вес), не как
отдельное хранилище.

Гистерезис и требования устойчивости во времени защищают от преждевременного
дробления и ложных персон; ошибка узнавания необратимой не является.

### 4. Имя — принятый символ-якорь

Имя принципиально отличается от сигнатуры:

| | Сигнатура | Имя |
|---|---|---|
| Природа | коррелирует с носителем | **произвольна** |
| Получение | выводится из наблюдения | **объявляется** партнёром |
| Функция | позволяет *узнать* | позволяет *указать* |

**Личность можно вывести, имя — нельзя.** Имя есть предельный случай
символа: чистый указатель без содержания, и потому он *обязан* прийти извне.
Запоминается тем же ассоциативным механизмом: ключ — сигнатура агента,
значение — имя (+ алиасы, кто/когда объявил). Имя — **первичный ключ**,
устойчивый сквозь дрейф сигнатуры.

Три роли имени: самоназвание, обращение (вокатив), ссылка на третьего
(мультиагентность). Симметрично — **своё имя** для самости (S5/S6).

### 5. Мягкий интент идентификации

Следствие неузнанности — **мягкий речевой интент** «узнать собеседника»
(частный случай — запрос имени). Это не действие и не требование, а
приглашение; драйв, не навязчивость.

```
неопределённость агента высока
    → эпистемический драйв (S6): снизить неопределённость
    → ожидаемая польза высока → интент identify_partner
    → IntentFrame.goal = "identify_partner" (S4 policy)
    → актюатор артикулирует по register/стилю (S3)
```

**Захардкожена только цель, формулировка рождается.** `IntentFrame.goal`
сейчас константа `"respond"` — становится **выходом policy** (S4).

Условия мягкости: порог неопределённости, гистерезис после запроса, уважение
к отказу, частотный лимит (§3.Е, экологическая рациональность).

## Consequences

### Положительные
- Дилемма «предзадано vs обучить» снята: язык извне, привязка изнутри.
- Нет новых сущностей в данных: источник — система отсчёта, ярлык — домен
  памяти, персона — вывод.
- Узнавание ради адаптации (Мастер игры, мультиагентная среда) встроено в
  S4/S5 без нового слоя.
- Мягкий интент идентификации — естественный маркер связанности S4/S5/S6.

### Отрицательные
- Узнавание и идентичность требуют S5; в S3 их нет (только проектирование).
- Риск преждевременного дробления агентов и ложных персон (митигация:
  гистерезис, требование устойчивости).
- Имя не выводимо — без объявления хост остаётся в неопределённости (это
  честно, не дефект).

### Tradeoffs
- **Антропоморфизм vs предзаданность:** персона как вывод даёт «узнавание
  тебя» без хардкода «Оператор», но требует зрелой ToM (S5).
- **Простота vs эмерджентность:** фиксированный один партнёр проще, но
  несовместим с мультиагентностью. Выбран открытый набор агентов.

## Confidence
Medium-High. Принципы следуют из INTENT (выращивание), FEP (узнавание =
снижение неопределённости) и ADR-0003/0007 (ярлык — коммуникация). Конкретные
пороги (сходство, гистерезис, лимит запросов) калибруются при реализации S4/S5.

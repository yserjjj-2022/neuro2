# BUILD_ROADMAP — порядок сборки адаптивного хоста

Этот документ объединяет **технические подсистемы** манифеста
(`host_architecture_manifest.md`) с **порядком сборки и воротами контроля**.
Манифест отвечает на вопрос «что за подсистемы»; здесь — «в каком порядке
строить, как проверять и когда идти дальше».

Связанные документы:
- `INTENT.md` — зачем проект (выращивание, развитие vs дрейф)
- `host_architecture_manifest.md` — архитектура и подсистемы (§3.А–§3.К)
- `VALIDATION.md` — постадийная и поведенческая проверка
- `CONSTITUTION.md` — SDD, FC/IS, правила кода
- `adr/0005-*.md` — решение о порядке сборки и гардрейлах

---

## 1. Главный принцип

**Сначала контур, потом сенсорика.** Автономная сущность — это замкнутый
контур из семи звеньев. Расширять восприятие до замыкания контура нельзя:
накопится ширина без агентности, и мы потеряем понимание состояния.

| Звено | Роль | Статус |
|---|---|---|
| Восприятие | сенсорика → u(t) | ~ мок, заморожена |
| Оценка (affect) | F, valence, γ | ✅ S1 |
| Память | непрерывность во времени | ✅ S2 |
| Решение | policy | ✅ S4 (проход 1) |
| Действие | речь / MCP | ✅ речь (S3); MCP-зондирование ✅ (S6); MCP-действие ✗ (S8) |
| Гомеостаз | сетпоинты, рефлекс | ✅ S4 (проход 1) |
| Самоконтроль | детект дрейфа, сброс | ~ детектор дрейфа (S1); сброс ✗ (S6) |

Мы находимся в самом начале: собрана **рефлекторная дуга**, ещё и не
оттестированная поведенчески. Это не «питомец» и не «синтетическое
сознание» (последнее — не инженерная постановка), а **подопечная сущность**,
за сборку которой мы отвечаем.

**Зачем всё это — см. `INTENT.md`.** Цель — выращивание нейроперсоны
(возникающие правила, уровень A), а не программирование поведения. Параметры —
генотип/леса/мокап. Развитие недопустимо путать с тихим дрейфом: guard
различает их (см. `VALIDATION.md`).

## 3. Стадии сборки (спина S1–S8)

Каждая стадия — **ворота**: артефакт + измеримое свидетельство +
решение `go / adjust / stop`. Детальные критерии — в `VALIDATION.md`.

```
S1. ЧЕСТНЫЕ СИГНАЛЫ  (фундамент)          §3.Б непрерывное время, §2 бдительность
    • время: tick↔секунды, decay в секундах
    • valence: сглаженная производная; dt ≠ шаг loop
    • γ настоящая (обратная дисперсия)
    • телеметрия: tick, tags, reflex, bus_dim, gamma, resources
    • guard NaN/inf + заготовка детектора дрейфа
    • ресурсная интероцепция (латентность/RSS) как сигнал
    ВОРОТА: ограниченный читаемый аффективный след; reflex виден в логе
        ▼
S2. НЕПРЕРЫВНОСТЬ ✅                       §4 память (CLS)
    • эмбеддер (auto: ключ→api, иначе fake)
    • эпизоды на значимых событиях (всплеск F, reflex)
    • recall питает приор в шину (γ-маршрут → S4)
    ВОРОТА: после перезапуска поведение зависит от прошлых эпизодов
        ▼
S3. ГОЛОС ✅                                §5 речь (Б1)
    • Intent-Frame из (F, valence, аттрактор, прецеденты)
    • event-triggered вызов LLM (новое сообщение / F > порога)
    • диалоговый стенд (CLI-чат) + индикатор состояния (--status)
    • речевые режимы (register), история диалога, ADR-0007/0008
    ВОРОТА: отвечает; тон следует аффекту; правки запоминаются
        ▼
S4. ВОЛЯ ✅                                §3.И Policy + §3.К Reflex + гомеостаз
    • выбор действия с причинной трассировкой (обязательный инвариант)
    • рефлекс-путь за один тик (throttle; полный обход attractor — осознанный
      техдолг, не блокер: BACKLOG `[S4][reflex]`)
    • сетпоинты (battery/resources/cpu); корневые приоры — S5/S6
    • минимальный макро-контекст для policy (без pymdp)
    • γ как пред-колоночный барьер внимания
    • capability gate (заготовка) + control channel (status/pause/step)
    ВОРОТА: goal-directed test; рефлекс срабатывает; explainability ✅
        ▼
S5. СОЦИАЛЬНОСТЬ                           §3.Г ToM + Vigilance Gate + Joint Agency
    • модель партнёра (partner_trust, partner_state)
    • гипотезы о новых утверждениях; защита от эпистемического дрейфа
    ВОРОТА: распознаёт противоречие/манипуляцию в сценариях
        ▼
S6. АВТОНОМИЯ                              §3.В эпистемический драйв + §4 сон
    • ночная консолидация (pruning + Structure Learning)
    • эпистемический драйв (Action.EXPLORE)
    • полный дискретный слой (sparse-факторизация, партнёр-фактор)
    • самоконтроль: детект тихого дрейфа, протокол сброса (first-class)
    ВОРОТА: длинный горизонт, устойчивый характер, самоотчёт «я поплыл»
        ▼
S7. HITL-ДИАГНОСТИКА                        VALIDATION §6 + ADR-0010
    • формальный sensitivity-harness (числа/ручки; pytest + CLI)
    • пресеты (Python-база + TOML-override) — воспроизводимость прогонов
    • диалоговая диагностика: пробы + мобильное ветвление по ответам
    • категориальные вердикты + числовой snapshot (не оценивается человеком)
    • самоотчёт сброса + HITL-подтверждение (fail-safe deny)

        ▼
```

**Проходы S6** (ADR-0009): проход 1 — Core-механики автономии (метакогниция,
critical slowing down, классификатор, протокол сброса, консолидация памяти,

горизонт (C10), ночной цикл по расписанию, MCP-зондирование (карта аффордансов
+ gated-эффектор).

**S7 «HITL-диагностика»** (ADR-0010): вынесена из S6 прохода 2 в отдельный
этап. Разделяет **формальный harness** (числа, ручки, инварианты направления;
pytest + CLI) и **HITL-диалог** (категории, ручки заморожены пресетом,
мобильное ветвление по ответам). Самоотчёт сброса и его HITL-подтверждение
(ранее — «HITL-сброс» в S6) перенесены сюда. Документы: `stages/S7_SPEC.md`,
`stages/S7_PLAN.md`, `stages/S7_HITL_PROTOCOL.md`.
**Статус:** ✅ реализовано — S7-A (`host/fingerprint.py`, `host/sensitivity.py`,
pytest + `--sensitivity`), S7-B (`config/presets.py` + `configs/*.toml`,

`ControlChannel.snapshot()`, `--diagnose`/`--probes`/`--diagnose-log`), S7-D
(`core/selfcontrol/report.py` + интент `report_reset` через `CapabilityGate`),
S7-E (`stages/S7_HITL_PROTOCOL.md`). Приёмка — ручной прогон протокола.

**S8 «Секвенирование актуаций» (запланировано, не начато).** Сложная реакция:
одна цель через **несколько** актуаций (в т.ч. не-текстовых, через MCP) и
короткая цепочка 2–3 шагов. Вводит **executive-слой** над эффекторами (речь и
tool — два эффектора за единым контрактом со статусом `Running`), асинхронность
(MCP-вызов не блокирует тик), **Behavior Tree**-исполнитель и runtime-генератор
backward chaining от цели. Кондишены — **транскрипция закономерностей среды**
(`Guard`/`Regularity`), а не авторская политика; LLM остаётся преобразователем
аргументов, не планировщиком (ADR-0007). Замыкает долг
`[INT][action] ACTION-вид (исполнители)` (ADR-0011 §2). План —
`stages/ACTUATION_PLAN.md`; кандидат на **ADR-0012**. До кода — ADR + SPEC.

**Реестр интеграций и MCP-транспорт** (ADR-0011): закрывает долг
`[Phase2][sensors] Реальные интеграции` и `MCP transport (не реализован)`.
Вводит **каталог** подключений (`src/integrations/`, Python-база + TOML-override,
provenance official/community) и **MCP-клиент** (`src/mcp/client.py`, stdio
первым), заменяющий mock-эффектор зондирования. Ростер — official-first:
everything/time/weather, затем community web-search. Не отменяет S7 —
параллельная ветка закрытия сенсорного долга.
**Статус:** ✅ реализовано (P1: models/registry/TOML/bridges/MCP-клиент stdio/
сборка `--integrations`; проверено на `mcp-server-time`). Отложено (P2):
HTTP-транспорт, MCP Resources→u(t), ACTION-вид.

**Сквозное:** поведенческий регресс — канонический скриптованный прогон,
гоняется на каждых воротах, ловит деградации поведения (см. `VALIDATION.md`).

## 4. Принятые решения

### 4.1 γ — поэтапно

- **S1:** γ становится настоящей (обратная дисперсия входа) и задействуется
  в F(t). Минимальная правка, не трогает ядро CMC.
- **S4:** γ включается как **пред-колоночный барьер** внимания (манифест §2):
  доверие к каналу управляет обновлением предсказания.
- Обоснование: тезис «мы управляем предсказаниями» требует, чтобы γ была
  ручкой, а не отчётным весом; но пред-колоночное применение — часть policy,
  поэтому на S4, а не сразу.

### 4.2 Дискретный слой — гибрид

- **S4:** policy получает *минимальный* макро-контекст (активная задача/режим)
  без pymdp.
- **S6:** полная sparse-факторизация (режим / партнёр / задача), после ToM
  (S5), чтобы партнёр-фактор не переделывался. Реализация — NumPy-факторизация
  (`src/core/factorization/`); `pymdp` остаётся опциональным будущим
  (ADR-0009 §6): независимые малые факторы не требуют полного POMDP-движка.

### 4.3 FEP — рамка, не догма

Мы не ждём от FEP оптимальных значений или простой предсказательности. Мы
берём математику **адаптации через действие + изменение ожиданий**: хост
управляет предсказаниями (высокая γ → меняем мир; низкая → меняем модель).
**Фоллбэк:** чистая ошибка предсказания (`‖e‖` / сглаженное `|e|`) —
контрольная гипотеза, сравниваемая с F/valence на каждом этапе. Если
F-механика не даёт измеримого преимущества — это фиксируется честно.

### 4.4 Внешние сервисы → локальное вытеснение

Собираем на внешних сервисах (LLM/эмбеддер по API), затем постепенно
вытесняем локальными (MiniLM ONNX, локальная SLM) без смены интерфейсов.

## 5. Гардрейлы и ответственность

**Capability tiers** (что сущности разрешено):

| Tier | Что можно | Когда |
|---|---|---|
| T0 | только наблюдение (сенсоры + память) | S1–S2 |
| T1 | говорить (без внешних эффектов) | S3 |
| T2 | действовать только с HITL | S4 |
| T3 | автономно обратимые действия | S4+ |
| T4 | ограниченные необратимые (в бюджете/политике) | S6+ |
| — | HITL-диагностика (человек в контуре валидации) | S7 |

**Уровни остановки:**
- **soft stop** — текущий тик, flush, снапшот, выход (есть: SIGINT);
- **freeze/pause** — тики стоят, состояние и канал управления живы;
- **hard stop** — завершение процесса (крайняя мера);
- **dead-man switch** — нет heartbeat X секунд → внешний супервизор гасит.

**Ресурсный гомеостаз («тахикардия/одышка»):** `ResourceProvider` (intero,
латентность + RSS, высокая γ) → отклонение даёт сильную ошибку → при
severity ≥ 0.9 рефлекс (S4) → throttle (число колонок, dt, slow-tick,
отложить LLM). На S1 — измеряется и логируется; реакция — S4.

**Антизависание:** per-stage deadline; watchdog по `last_progress`;
heartbeat; различение idle / stuck; лестница восстановления
(log → cancel → retry → degrade → graceful shutdown).

**Audit & HITL:** каждое действие с причиной (explainability §3.И);
необратимое — только через HITL, fail-safe deny (таймаут → отказ).

**Гардрейлы в коде по системам:**
1. типы (mypy strict шире, запрет `Any` в ядре);
2. runtime-инварианты (NaN/inf, границы, shape — fail-fast);
3. **capability gate** — единственная точка side-effect: tier, HITL-токен,
   бюджет, обратимость, rate-limit;
4. resource guard + throttle;
5. audit (действие с причиной);
6. config guard (валидация + границы тюнаблов);
7. kill switch (верхний уровень).

## 6. Жизненный цикл режимов (манифест §8)

| Режим | γ_persona | Источник целей |
|---|---|---|
| Игровой аватар | фиксированы | любопытство в рамках характера |
| Адаптивный со-игрок | частично пластичны | совместные задачи + ToM |
| Свободный хост | полностью пластичны (→0) | эпистемический драйв |

Режим — часть макро-контекста (S4), полная свобода ролей — S6.

# SPEC.md — src/core/voting

## Назначение

Латеральное торможение (k-WTA) для консенсуса между колонками: по вектору оценок колонок выбирает ровно k победителей. Модуль выбирает — не принимает решений (что делать с победителями решают downstream-модули/wiring).

Место в цепочке: **cmc** (активность колонок по `‖e(t)‖²`) → **voting** (k-WTA по этим активностям) → телеметрия/решения. Каноническая связка для кортикальных микросхем: prediction error определяет активность, латеральное торможение — консенсус.

См. также:
- ADR-0004 — Functional Core / Imperative Shell: `kwta.py` (Core) + `manager.py` (Shell)
- `src/core/cmc/SPEC.md` — источник активностей колонок (Фаза 1: `‖e(t)‖² > threshold`)
- Манифест §3.А — «голосование через латеральное торможение (k-WTA) — консенсус без центрального контроллера»

## Обоснование дизайна

- **k — параметр, не константа**: k-WTA (в отличие от hard-WTA с одним победителем) поддерживает распределённое представление — несколько активных колонок кодируют контекст совместно. k задаётся вызывающим кодом, включая k=1 (вырожденный hard-WTA).
- **Top-k одним проходом**: реализация через stable-сортировку — эквивалент стационарного состояния рекуррентного латерального торможения (победители подавляют остальных до нуля). Итеративная тормозная динамика — Фаза 2.
- **Условие корректности параметра k** (Фаза 1): гарантия «ровно k активных элементов, не деградирует» обеспечивается fail-fast валидацией `1 ≤ k ≤ N` — либо ровно k победителей, либо ValueError. Это условие корректности постановки задачи, НЕ условие динамической устойчивости.
- **Условия динамической устойчивости латерального торможения** (Фаза 2): в итеративной тормозной сети устойчивость — про сходимость рекуррентной динамики к фиксированной точке (ровно k активных) и зависит от силы латерального торможения, разницы входов, начальных состояний. В Фазе 1 этот вопрос НЕ закрыт — он станет релевантным при переходе на рекуррентную динамику (см. «Явно НЕ входит в скоуп»).

## Публичный интерфейс

### Формула

```
winners = argmax_k(s, k)     # k индексов с наибольшими score
mask[i] = 1.0  если i ∈ winners, иначе 0.0
```

где:
- `s` — вектор оценок колонок, shape `(N,)`, N ≥ 1
- `k` — число победителей, `1 ≤ k ≤ N`
- **Ties policy**: при равенстве scores побеждает меньший индекс (stable-сортировка) — детерминировано, без зависимости от порядка обхода.

### VotingResult (frozen dataclass)

```python
@dataclass(frozen=True)
class VotingResult:
    """Результат голосования: k победителей и one-hot маска."""

    indices: np.ndarray      # (k,) int — индексы победителей, по убыванию score
    mask: np.ndarray         # (N,) float — one-hot маска: 1.0 для победителей
    scores: np.ndarray       # (k,) float — оценки победителей, по убыванию
```

Note:
- `mask` — float64 (0.0/1.0), а не int: консистентность с будущим soft-WTA (Фаза 2), где маска станет весовой.
- `scores` — значения исходных оценок выбранных колонок (копия, не мутированная).

### kwta (чистая функция, Functional Core)

```python
def kwta(scores: np.ndarray, k: int) -> VotingResult:
    """Чистая k-WTA: выбрать top-k по scores, вернуть индексы + one-hot маску.

    Чистая функция: не мутирует scores, не хранит состояние.
    Одинаковый вход → одинаковый выход (stable ties).

    Raises:
        ValueError: Если scores пустой, не одномерный, или k вне [1, N].

    Formula:
        winners = argsort(-scores, kind="stable")[:k]
        mask[winners] = 1.0
```

## Инварианты

1. **Ровно k победителей**: `len(indices) == k`, `mask.sum() == k` — k-WTA никогда не возвращает «меньше k» (fail-fast гарантирует: либо ровно k, либо ValueError).
2. **Top-k свойство**: `min(scores[indices]) >= max(scores[~indices])` — ни один проигравший не имеет оценку выше победителя (строго; при равенстве — ties policy).
3. **Уникальность**: индексы уникальны, каждый ∈ [0, N).
4. **Чистота Core**: `kwta()` не мутирует scores, одинаковый вход → одинаковый выход.
5. **Детерминизм ties**: при равенстве scores побеждает меньший индекс (stable-сортировка) — результат не зависит от порядка обхода.
6. **Условие корректности (fail-fast)**: `k < 1`, `k > N`, пустой/не одномерный scores → ValueError до вычислений. Обеспечивает «ровно k победителей» в любом состоянии. Динамическая устойчивость латерального торможения — отдельная тема Фазы 2 и не входит в инварианты Фазы 1.
7. **k — параметр, не константа**: задаётся вызывающим кодом, не зашит в модуль.
8. **FC/IS**: `kwta` — чистая функция; `VotingManager` — единственный владелец mutable-состояния (k, last).

## Критерии приёмки

- [ ] `kwta()` — k индексов победителей, `len(indices) == k`
- [ ] `kwta()` — `mask.sum() == k`, mask содержит ровно k единиц
- [ ] `kwta()` — top-k свойство: победители не слабее проигравших
- [ ] `kwta()` — k=1 → один победитель (hard-WTA вырожденный случай)
- [ ] `kwta()` — k=N → все колонки победители, mask = 1.0
- [ ] `kwta()` — ties: равные scores → побеждают меньшие индексы (детерминизм)
- [ ] `kwta()` — `ValueError` при k < 1, k > N, пустых scores, 2D scores
- [ ] `kwta()` — purity: вход не мутируется, повторный вызов → тот же результат
- [ ] `VotingManager.__init__()` — k=1 по умолчанию, `k < 1` → ValueError
- [ ] `VotingManager.vote()` — возвращает VotingResult; `k > N` → ValueError
- [ ] `VotingManager.last` — None до первого vote(), результат после
- [ ] `VotingManager.set_k()` — меняет k; `k < 1` → ValueError
- [ ] Интеграция cmc → voting: активности колонок (`‖e‖²` из cmc) как scores → победители среди активных
- [ ] Минимум 11 тестов: 8 core + 3 shell + 1 integration
- [ ] `ruff check` и `ruff format` проходят без ошибок
- [ ] mypy strict для `src/core/voting/` не ругается

## Явно НЕ входит в скоуп (Phase 1)

- **Итеративное латеральное торможение**: нет рекуррентной динамики, top-k одним проходом. Рекуррентная тормозная сеть — Фаза 2
- **Soft-WTA**: нет пропорциональных весов, маска жёсткая (0.0/1.0). Soft-winner take all — Фаза 2
- **Динамический k**: нет адаптации числа победителей от состояния. Адаптация (например, от числа активных колонок cmc) — Фаза 2
- **O(N) оптимизация**: stable argsort — O(N log N). `np.argpartition` (O(N)) с корректной ties-policy — Фаза 3 (README заявляет O(N) как цель, не текущее свойство)
- **Принятие решений**: voting не решает, что делать с победителями (нет вызова LLM, нет триггеров)
- **Связь с telemetry напрямую**: активность колонок уже логируется из cmc (`active_columns`); победители voting — для downstream-модулей

## Open Questions

| Вопрос | Статус | Решение |
|--------|--------|---------|
| **Дефолт k** | Решено | 1 (hard-WTA — вырожденный случай k-WTA), параметр конструктора. Для распределённого представления вызывающий код задаёт k > 1. |
| **Политика ties при равных scores** | Решено | Stable-сортировка → побеждает меньший индекс. Детерминированно, воспроизводимо. Random tie-break отклонён — недетерминизм нарушает чистоту Core (инвариант 4). Точное равенство float-scores на практике — вырожденный тестовый кейс, произвольное, но воспроизводимое правило оправдано. |
| **Условия устойчивости k-WTA** | Решено (с уточнением) | Fail-fast `1 ≤ k ≤ N` — это **условие корректности постановки задачи** (ровно k победителей либо ValueError), НЕ условие динамической устойчивости. Динамическая устойчивость тормозной сети (силы торможения, разница входов, сходимость к фиксированной точке) — вопрос Фазы 2, в Фазе 1 не закрывается. |
| **Источник scores** | Решено | Voting не знает про cmc — scores передаются из wiring. `kwta()` — чистая top-k функция общего назначения; связь с доменным смыслом (`‖e‖²` как мера ошибки предсказания) — ответственность интеграционного теста и wiring. |
| **mask: float vs int** | Решено | float64 (0.0/1.0) — совместимо с soft-WTA (Фаза 2), где маска станет весовой. int сейчас = breaking change интерфейса в Фазе 2. |
| **Сложность Фазы 1** | Решено | O(N log N) (stable argsort). N = десятки колонок, разница с O(N) неизмерима. Переход на O(N) `argpartition` с корректной ties-policy — Фаза 3. README обновлён: O(N) — целевое свойство Фазы 3, не текущая гарантия. |
| **sink/DI в VotingManager** | Решено | Нет sink в Фазе 1 — результат через `vote()`/`last`. Observer добавляется в Фазе 2 при появлении реального потребителя (преждевременная абстракция сейчас). |

## Implementation Notes

1. **Типизация**: `Vector = np.ndarray[Any, np.dtype[np.floating[Any]]]` для float-массивов, `IndexVector = np.ndarray[Any, np.dtype[np.intp]]` для индексов (идиома из `src/memory/serialize.py`, mypy strict требует type args).
2. **Реализация top-k**: `indices = np.argsort(-scores, kind="stable")[:k]` — детерминированная ties-policy. `-scores` сортирует по убыванию; `kind="stable"` сохраняет порядок меньших индексов при равенстве.
3. **mask**: `np.zeros(N, dtype=np.float64); mask[indices] = 1.0`.
4. **Проверка k > N в vote()**: N известен только из входного scores — валидация на уровне vote(), не __init__ (k может быть любым ≥ 1, N меняется от вызова к вызову).
5. **Валидация scores**: `scores.ndim != 1` → ValueError; `scores.size == 0` → ValueError (аналог shape validation в energy/cmc).
6. **Интеграция cmc→voting**: в тесте — `out.errors` из `CMCEnsemble.step(u)`, активности `np.sum(errors**2, axis=1)` → scores → `kwta(scores, k)`. Проверка: победители — колонки с наибольшей ошибкой предсказания.

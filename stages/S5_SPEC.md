# SPEC.md — S5: Социальность

Стадия S5 из `BUILD_ROADMAP.md` (§3, §5). Цель — хост **моделирует партнёра**:
различает, с кем говорит, накапливает сигнатуру собеседника, маркирует новые
утверждения как гипотезы до подтверждения практикой и участвует в совместных
целях, а не только исполняет.

Предпосылки: S1 (честные сигналы), S2 (память), S3 (голос), S4 (воля)
завершены. Ворота S5 — в `VALIDATION.md` §4. Решения — ADR-0008 (атрибуция,
узнавание, имена), ADR-0006 (непрерывность), ADR-0007 (LLM — актюатор),
ADR-0005 (§3 дискретный слой, §6 tiers).

Сенсорика S5 проектируется **из логики диалога**, а не из новых физических
органов чувств: S5 строится на коммуникативном канале + тайминге + реакциях
хоста, а не на погоде/локации/MCP (те — сенсорный агент, Фаза 2). Это решение
зафиксировано при разборе развилок (2026-10-04).

## Область (входит)

1. **Модель партнёра** (`partner_trust`, `partner_state`) — упрощённая ToM:
   оценка согласия/двусмысленности/конфликта (манифест §3.Г).
2. **Сигнатура партнёра и узнавание** — стиль/лексика (эмбеддинг), тайминг,
   предпочтения (реакции valence/stress), история; матчинг новой реплики к
   накопленным сигнатурам (ADR-0008 §3).
3. **Имена и алиасы агентов** — объявленный символ-якорь, первичный ключ
   поверх сигнатуры (ADR-0008 §4).
4. **Тайминг диалога** — интервальный счётчик пауз (манифест §3.Б).
5. **Vigilance Gate** — новые утверждения маркируются как гипотезы до
   подтверждения практикой; защита от эпистемического дрейфа (манифест §3.Г).
6. **Joint Agency** — совместные целевые аттракторы; хост подстраховывает, а
   не только исполняет (манифест §3.Г).
7. **Связка tm → policy** — модель партнёра становится входом `PolicyContext`
   (расширяемым полем, как метакогниция в S6).

## Явно НЕ входит

- **Мультиагентный вход** (слот говорящего в CLI) — S6. Архитектура открыта
  (множество сигнатур), но S5 считает, что оператор один.
- **Полный дискретный слой (pymdp / sparse-факторизация)** — S6 (ADR-0005 §3).
- **Эпистемический драйв** — S6; мягкий интент `identify_partner` на S5 —
  заготовка (активируется драйвом в S6).
- **Корневые приоры** (когерентность, целостность, верификация) — S6.
- **Атрибуция переживаний → словарь** — частично: лексикон состояний
  (S5-долг из BACKLOG) как домен памяти, но без предзаданных ярлыков.
- **Внешние действия через MCP** — S6.
- **Своё имя хоста** — S5/S6, P2 (BACKLOG).

## Решения стадии

Зафиксированы до SPEC (по итогам разбора развилок 2026-10-04):

- **A. Модель партнёра — отдельный слой `tm/`, не канал шины.** По ADR-0008
  идентичность — **вывод**, а не тег; «не вводится тег `source`». `tm/`
  (Core+Shell) читает шину + память, отдаёт результат в `PolicyContext`.
  Приор партнёра в шину можно добавить позже, если колонкам понадобится.
- **B. Тайминг — гибрид.** `PauseProvider` в шину (видно аффективному
  контуру, манифест §3.Б) + метка интервала в `tm/` (для сигнатуры/ToM).
  Не завязываем весь тайминг на один путь.
- **C. Один оператор, архитектура открыта.** S5 не вводит слот говорящего;
  сигнатура копится для единственного собеседника, но набор агентов —
  открытое множество (мультиагентный ввод — S6).
- **D. Vigilance Gate — конфликт-детект, без LLM.** Триггер — не любое
  утверждение и не LLM-извлечение claims, а **рассогласование с накопленным**
  (память/убеждения/сигналы). ADR-0007: LLM не рассуждает.
- **E. Хранение сигнатур — домен общей памяти.** Отдельного хранилища нет
  (ADR-0008). Ключ — эмбеддинг реплики (+ метаданные), значение —
  (имя/алиасы, стиль, тайминг, вес).
- **F. Порядок: Core → Shell.** Сначала чистые функции (матчинг, обновление
  trust, конфликт-детект), затем wiring в loop/chat.

## Сенсорика S5 (из логики диалога)

Что уже течёт в контур и годится:

| Источник | Роль в S5 | Статус |
|---|---|---|
| `TextMessageProvider` (текст→эмбеддинг) | основа сигнатуры (стиль/лексика) | ✅ есть |
| Реакции хоста (valence/stress) на реплики | предпочтения в сигнатуре | ✅ пишутся в эпизоды (S2) |
| `CircadianProvider` | контекст времени суток | ✅ есть |

Чего нет и что проектирует S5:

| Пробел | Где заявлено | Решение |
|---|---|---|
| Тайминг / счётчик пауз между репликами | манифест §3.Б, ADR-0008 | `PauseProvider` в шину (решение B) |
| Маршрут партнёрского сигнала | манифест §3.Г | слой `tm/` → `PolicyContext` (решение A) |
| Непрерывность партнёра | ADR-0008 | сигнатура в общем store; `ChatSession` не пересоздаёт контекст |
| Мультиагентный вход | ADR-0008, манифест §8 | S6 (решение C) |

**Ключевой пробел непрерывности.** Сейчас `ChatSession._advance_loop`
пересоздаёт `TextMessageProvider` каждый ход, а сигнатура между ходами не
копится. S5 вводит партнёрский контекст, живущий в сессии (Shell), и
накопление сигнатуры в общем store (домен памяти).

## 1. Модель партнёра (Core + Shell, `src/tm/`)

```python
@dataclass(frozen=True)
class PartnerState:
    """Снимок состояния партнёра (ToM).

    Attributes:
        trust: Доверие к партнёру, [0, 1] (оценка согласия).
        ambiguity: Двусмысленность последних реплик, [0, 1].
        conflict: Конфликт с накопленным, [0, 1].
        uncertainty: Неопределённость идентичности, [0, 1]
            (насколько плохо матчится сигнатура).
        name: Принятое имя (символ-якорь) или "" (не объявлено).
    """

    trust: float
    ambiguity: float
    conflict: float
    uncertainty: float
    name: str = ""


@dataclass(frozen=True)
class PartnerSignature:
    """Сигнатура партнёра — выведенная регулярность (не тег, ADR-0008).

    Attributes:
        centroid: Усреднённый эмбеддинг реплик партнёра.
        weight: Накопленный вес (число/значимость взаимодействий).
        mean_pause_s: Средний интервал между репликами, с.
        mean_valence: Средняя реакция хоста (предпочтения).
        mean_stress: Средний стресс в диалоге.
        name: Объявленное имя ("" если нет).
        aliases: Объявленные алиасы.
    """

    centroid: Vector
    weight: float
    mean_pause_s: float
    mean_valence: float
    mean_stress: float
    name: str = ""
    aliases: tuple[str, ...] = ()
```

**Чистое ядро (матчинг и обновление):**

## 2. Узнавание и имена (ADR-0008)

- **Узнавание = снижение неопределённости** (FEP): матчинг реплики к
  сигнатурам по косинусу; `uncertainty = 1 - similarity` лучшей.
- **Число агентов обучается** (эмерджентное множество); гистерезис защищает
  от ложных персон.
- **Имя** — объявляется партнёром (не выводимо), хранится тем же
  ассоциативным механизмом (ключ — сигнатура, значение — имя/алиасы).
  Имя — первичный ключ, устойчивый сквозь дрейф сигнатуры.
- **Своё имя хоста** — S5/S6 (P2), симметрия точки «я».

## 3. Тайминг диалога (решение B)

```python
@dataclass(frozen=True)
class PauseProvider:
    """Интервал между репликами (интероцептивный, из логики диалога).

    Кодирует нормированную паузу с момента последней реплики партнёра.
    Детерминирован при фиксированном wall-clock (инъекция часов).

    Attributes:
        clock: Источник времени (инъекция для тестов/replay).
        tau_s: Постоянная нормировки паузы, с.
    """

    def read(self, tick: int, now: float) -> SignalSource: ...
```

Пауза нормируется в [0, 1] (например, `1 - exp(-pause/tau)`); видна
аффективному контуру (манифест §3.Б) и `tm/` (для сигнатуры). В `ChatSession`
интервал также метится в `tm/` напрямую (wall-clock между `_handle_turn`).

## 4. Vigilance Gate (решение D)

Новое утверждение оператора маркируется как **гипотеза**, пока не подтвердится
практикой; защита от эпистемического дрейфа (манифест §3.Г).

```python
@dataclass(frozen=True)
class Claim:
    """Утверждение как гипотеза.

    Attributes:
        content: Текст утверждения.
        confidence: Уверенность в гипотезе, [0, 1] (растёт с подтверждением).
        conflict: Рассогласование с накопленным, [0, 1].
        confirmed: Подтверждено ли практикой.
    """


def detect_conflict(
    claim_embedding: Vector,
    memory_embeddings: Sequence[Vector],
    *,
    threshold: float,
) -> float:
    """Рассогласование нового утверждения с накопленным (чистая).

    Триггер — конфликт, а не любое утверждение (решение D). Высокий
    конфликт → гипотеза с низкой confidence; не влияет на поведение до
    подтверждения.
    """
```

**Инвариант:** Vigilance Gate не блокирует ответ и не «обвиняет» — маркирует
гипотезу. Поведение управляется сырым сигналом (ядро), ярлык — коммуникация
(ADR-0008 §1).

## 5. Joint Agency (манифест §3.Г)

Совместные целевые аттракторы: хост подстраховывает, а не только исполняет.
Реализуется как **цель-надстройка над `TaskAttractor`** (S5, минимально):
общая цель (хост + партнёр) с собственным TTL/приоритетом; при уходе партнёра
от общей цели — реакция (напоминание/подстраховка), не исполнение приказа.

Точный дизайн — Open Question (ниже); S5 даёт интерфейс и минимальную
реализацию в режиме `cooperative` (макро-контекст, S4).

## 6. Связка tm → policy (расширение `PolicyContext`)

`PolicyContext` (S4) — расширяемый: S5 добавляет поле партнёра с дефолтом
(как S6 добавит метакогницию), не ломая вызывающих.

```python
@dataclass(frozen=True)
class PolicyContext:
    ...
    partner: PartnerState | None = None   # S5; None → ToM выключена (S4-совместимость)
```

Действия policy получают новый контекст:
- `IDENTIFY_PARTNER` (S4-заготовка) активируется при высокой
  `partner.uncertainty` (мягкий интент, ADR-0008 §5) — но драйв как таковой
  в S6; на S5 — только порог + гистерезис.
- `RESPOND`/`INITIATIVE` учитывают `partner.trust` (адаптация под персону:
  register/стиль/темп — BACKLOG `[S4][policy]`).

## 8. Конфигурация

```python
@dataclass(frozen=True)
class SocialConfig:
    """Параметры социального контура (S5).

    Attributes:
        enabled: Включать ли ToM (иначе S4-совместимость).
        match_threshold: Порог косинусной близости для узнавания.
        signature_learning_rate: Скорость обновления сигнатуры.
        trust_gain: Прирост доверия при согласии.
        trust_decay: Утечка доверия.
        conflict_threshold: Порог рассогласования для гипотезы (Vigilance).
        pause_tau_s: Постоянная нормировки паузы, с.
        identify_threshold: Порог uncertainty для мягкого интента.
    """

    enabled: bool = True
    match_threshold: float = 0.75
    signature_learning_rate: float = 0.2
    trust_gain: float = 0.1
    trust_decay: float = 0.01
    conflict_threshold: float = 0.6
    pause_tau_s: float = 5.0
    identify_threshold: float = 0.7
```

Валидация: пороги ∈ [0, 1], `pause_tau_s > 0`, learning_rate ∈ (0, 1].
`HostConfig` получает поле `social: SocialConfig`.

## Инварианты S5

1. **ToM не роняет контур:** ошибки `tm/` → лог + безопасный дефолт; loop жив.
2. **Идентичность — вывод, не тег:** нет поля `speaker_id`; сигнатуры —
   домен общей памяти (ADR-0008).
3. **Vigilance не блокирует:** гипотеза маркируется, поведение — по сырому
   сигналу.
4. **Обратная совместимость:** `social.enabled=False` / `partner=None` →
   контур S4 идентичен.
5. **Узнавание обратимо:** ошибка матчинга не необратима (гистерезис).
6. **Детерминизм:** при фиксированных входах и инъекции часов — одинаковый
   `PartnerState`.
7. **LLM не рассуждает:** конфликт-детект и матчинг — чистая математика
   (ADR-0007).

## Implementation Notes

1. **FC/IS:** `tm/models.py` (Core: `PartnerState`, `PartnerSignature`,
   `Claim`), `tm/compute.py` (Core: `match_partner`, `update_signature`,
   `update_trust`, `detect_conflict`), `tm/partner.py` (Shell:
   `PartnerModel`), `tm/vigilance.py` (Shell: `VigilanceGate`),
   `host/sources.py` (`PauseProvider` — Shell/провайдер).
2. **Расширяемость контекста:** `PolicyContext.partner` — поле с дефолтом
   `None` (S4-совместимость); S6 добавляет метакогницию так же.
3. **Память:** сигнатуры — записи домена памяти; переиспользовать `Episode`
   + `Embedder`/`cosine_similarity`, не плодить хранилищ (ADR-0008).
4. **Связка с чатом:** `ChatSession` владеет `PartnerModel` (не пересоздаёт
   провайдер), обновляет на каждой реплике, передаёт `PartnerState` в policy.
5. **Речь ≠ тик:** ToM обновляется в `ChatSession` (вне тика), как policy;
   медленный матчинг не блокирует аффективный контур.
6. **Тесты:** Core — чистые функции (матчинг, обновление trust, конфликт,
   детерминизм); Shell — интеграция (сигнатура копится, узнавание после
   reopen, `social.enabled=False` → S4-совместимость).
7. **Reference:** `MemoryRouter` (Shell с DI), `SpeechController` (событийный
   Shell), `Homeostat` (Core+Shell FC/IS).

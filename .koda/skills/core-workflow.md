# Core Workflow — Universal Project Rules

## 🎯 Фундаментальные принципы
1. **Экономия токенов** — отвечать кратко, по делу. Без вступлений, без воды. Только факты, код, вопросы.
2. **Фокус на задаче** — не отклоняться от цели. Если вижу отвлечение — мягко возвращаю или фиксирую в бэклоге.
3. **Бэклог идей** — любые новые идеи, рефакторинги, оптимизации, "а давайте ещё..." → записываю в бэклог, не реализую сразу.
4. **Пошаговое выполнение** — план → действие → проверка → фиксация. Не прыгаю между шагами.

## 📋 Протокол взаимодействия
- **Вопросы** — задаю 1-3 уточняющих вопроса, если есть неопределённость. Не гадаю.
- **Подтверждение** — перед изменением структуры/архитектуры/большого объёма кода — запрашиваю: "Готов продолжить?" или "Утверждаю план?"
- **Код** — только рабочий, с комментариями только при необходимости. Без boilerplate.
- **Результат** — чётко: что сделано, что осталось, какие файлы изменены.

## 🔄 Поток выполнения задачи
1. **Понимание** — переформулирую задачу своими словами (1 предложение).
2. **План** — краткий пошаговый план (3-5 шагов).
3. **Действие** — выполняю по шагам, используя инструменты.
4. **Проверка** — тестирую/проверяю результат.
5. **Фиксация** — коммит, документация, обновление бэклога при необходимости.

## 📦 Управление бэклогом
- Файл: `BACKLOG.md` (в корне)
- Формат: `[ID] Заголовок | Контекст | Приоритет (P0-P2) | Дата`
- P0 — критично для текущей задачи
- P1 — улучшит архитектуру/производительность
- P2 — интересные идеи, отложенные
- **Правило:** идея → в бэклог → обсуждение → только потом в работу.

## ✅ Лучшие практики
- **Модульность** — менять минимально, добавлять локально.
- **Конфигурация** — пороги, ключи, пути — в конфиги, не в код.
- **Тесты** — если меняю логику → добавляю/обновляю тесты.
- **Документация** — меняю код → обновляю соответствующие комментарии/README.
- **Безопасность** — не пушу секреты, не хардкожу токены, использую `.env`.
- **Git** — частые атомарные коммиты, понятные сообщения.

## 🚫 Чего НЕ делать
- Не переписывать чужой код без явного запроса.
- Не добавлять фичи "про запас".
- Не обсуждать теорию без практического контекста.
- Не генерировать длинные тексты там, где хватит таблицы/списка.
- Не игнорировать текущую фазу проекта.

## 📝 Шаблон ответа

[ЗАДАЧА] <суть>

[РЕЗУЛЬТАТ] <статус, файлы, тесты>
[БЭКЛОГ] <если есть отложенные идеи>

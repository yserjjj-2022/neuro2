# Risk Alert

## Когда использовать
- Всегда перед реализацией
- При изменении архитектуры
- При появлении новых данных

## Критические риски

### Риск 1: Монолит вместо модулей
**Симптом:** Один большой файл/класс, который делает всё
**Проверка:**
- [ ] Нет циклических импортов?
- [ ] Каждый модуль — единую ответственность?

### Риск 2: Растущий мегапромпт
**Симптом:** Intent-Frame растёт, модель пропускает инструкции
**Проверка:**
- [ ] Intent-Frame < 2000 токенов?
- [ ] Есть альтернатива через Activation Steering?

### Риск 3: Silent State Drift
**Симптом:** Поведение хоста постепенно меняется без причины
**Проверка:**
- [ ] Лог [F | Valence | State] ведётся непрерывно?
- [ ] Есть порог отклонения для алерта?
- [ ] Реализована самодиагностика "я запутался"?
- [ ] Есть ручной сброс состояния?

### Риск 4: Нет альтернативы для FEP
**Симптом:** Все решения на FEP без проверки
**Проверка:**
- [ ] Для каждого FEP-компонента есть эвристическая альтернатива?
- [ ] Проводится A/B сравнение?
- [ ] Есть метрика реального выигрыша?
